# 拓展功能实现说明（已实现本地演示 + 真机接入指南）

赛题要求的 4 个创新拓展功能**已全部实现为可编译、可单机演示的真实功能**，并在「我的 → 鸿蒙特色能力」中上线入口（绿色"已上线"标签）。

- 设计原则：**真机能力优先**（选图、通知、系统分享均调用系统真实 API）；需要多设备/闭源视觉/服务端的能力，在**没有设备或 SDK 不支持时自动降级为本地模拟**，保证单机可完整演示。
- 真机/分布式/视觉/网络等能力的接入代码以**注释**或开关保留，接入步骤见本文各节"真机接入点"。
- 所有拓展遵循 ArkTS 严格模式，零第三方运行时依赖，数据统一落本地 SQLite（`carbon_footprint.db`）。

| 功能 | 页面 | 能力门面 / 数据层 | 演示模式 |
|---|---|---|---|
| 超级终端·家庭合并 | `pages/FamilyPage.ets` | `features/terminal/SuperTerminal.ets`、`data/repository/FamilyRepository.ets` | 本地模拟超级终端 |
| 端侧 AI 识图 | `pages/AiRecognizePage.ets` | `features/ai/BehaviorRecognizer.ets` | 真实选图 + 本地演示识别引擎 |
| 城市碳普惠 | `pages/CarbonInclusivePage.ets` | `features/platform/CarbonInclusiveClient.ets`、`data/repository/PlatformRepository.ets` | 本地 Mock 平台 |
| 智能服务 | `pages/SmartPage.ets` | `features/smart/SmartService.ets` | 真实通知/分享 + 本地规则 |

新增数据表：`family_members`（家庭成员）、`family_reduction`（成员每日分类减排）、`benefit_orders`（权益兑换订单）；`meta` 表新增 `platform_points`、`platform_last_sync` 键。

## 一、超级终端 · 多设备数据同步 · 家庭碳积分合并

### 已实现（可直接演示）
- 入口：「我的 → 📡 超级终端·家庭碳积分合并」。
- 家庭总览：家庭总减排量、总积分、覆盖设备数（手机/平板/手表）、成员数。
- 预置成员：爸爸 👨（手机）、妈妈 👩（平板）、孩子 👧（手表），并生成近 7 天确定性的减排数据。
- **一键同步**：模拟超级终端发现可信设备、跨设备拉取各成员当日减排，补齐当天数据并刷新合并统计。
- **成员减排排行**：含本人在内，按累计减排/积分排名，显示设备与在线状态。
- **家庭分类结构**：出行/节能/回收/惜粮四类家庭合计条形图。
- 支持内联弹窗**添加成员**、**删除成员**（重置后可恢复预置）。

### 关键文件
- 数据：`data/repository/FamilyRepository.ets`（`familyRepo`，建表/种子/同步/排行/分类聚合）。
- 门面：`features/terminal/SuperTerminal.ets`（`ENABLED=true`、`MODE='simulate'`）。
- 模型：`Models.ets` 中 `FamilyMember`、`MemberTotal`；常量见 `AppConstants.ets` 的 `TABLE_FAMILY_*`。

### 真机接入点（多设备真实同步）
1. `module.json5` 声明 `ohos.permission.DISTRIBUTED_DATASYNC`（user_grant，需弹窗授权）。
2. 用 `@kit.DistributedServiceKit` 的 `deviceManager`（或 `@ohos.distributedDeviceManager`）发现可信设备并组网。
3. 用 `@kit.ArkData` 的 `distributedKVStore` 上报当日摘要，键形如 `family/{familyId}/member/{deviceId}/{date}`；主机端订阅 `on('dataChange')` 聚合。
4. 明细级同步可用 `distributedRdbStore` 同步 `carbon_records`，为记录增加 `uuid`、`familyId`，合并按 `uuid` 去重，来源标记 `RecordSource.FAMILY`（已预留）。
5. 家庭组可通过短码/扫码完成"创建家庭 / 加入家庭"。

## 二、端侧 AI · 图片智能识别低碳行为并自动录入

### 已实现（可直接演示）
- 入口：「我的 → 📷 端侧 AI 图片智能识别」，或识图确认后进入录入。
- **相册选图为系统真实能力**：`@kit.MediaLibraryKit` 的 `photoAccessHelper.PhotoViewPicker`（安全选择器，**无需相册权限**），选中后真实回显图片。
- 提供"演示样例"按钮，便于无图片时演示。
- 识别流程（loading 动画）：
  1. 先按**文件名关键词**匹配行为（如 `bike/公交/光盘/回收/塑料/关灯/纸` 等）；
  2. 未命中则按图片 URI 稳定哈希在 12 个高频低碳行为中推断，置信度 0.62~0.95，结果稳定可复现；
  3. 结果标注"端侧识别·演示引擎"，展示命中行为、图标、置信度进度条。
- 识别后可调节数量，**实时核算**减排量与积分，点击"确认录入"自动写入记录（来源 `RecordSource.AI`，备注"AI识图：…"）。

### 关键文件
- `features/ai/BehaviorRecognizer.ets`：`pickImage()`（真实选图）、`recognize()`、`recognizeByLocalEngine()`；关键词映射 `KeywordBehaviorMap`。
- 页面：`pages/AiRecognizePage.ets`。

### 真机接入点（真实视觉推理）
- 开源 SDK 未包含 Core Vision Kit（`@kit.CoreVisionKit` 的 `imageClassification` 在本环境不可用），`recognizeWithCoreVision()` 已以注释保留：
  ```ts
  // import { imageClassification } from '@kit.CoreVisionKit';
  // const classifier = await imageClassification.create();
  // const result = await classifier.classify({ uri: imageUri });
  // 取置信度最高标签，经 KeywordBehaviorMap 映射为 behaviorId
  ```
- 在含视觉能力的工程/设备上：取消注释、把 `MODE` 切为 `coreVision`，并在 `module.json5` 声明 `ohos.permission.CAMERA`（拍照需要；相册选择由 Picker 授权，无需权限）。
- 低置信度/未命中时保留"转手动选择"的降级路径。

## 三、城市碳普惠平台对接 · 积分互通与权益兑换

### 已实现（可直接演示）
- 入口：「我的 → 🏙️ 城市碳普惠平台对接」。
- 账户卡：本地"碳积分"与平台"碳币"按 **1:1 互通**，一键同步把本地积分上报平台并记录同步时间（模拟网络延迟）。
- **权益商城**：8 项低碳权益（乘车券、公园门票、骑行月卡、环保袋、植树证书、咖啡券、充电券、生活缴费券等），两列网格展示。
- 兑换流程：积分校验 → 确认对话框 → 扣减本地积分（写 `point_records`，类型 `EXCHANGE`）→ 生成 `PT-` 核销码订单 → 回写平台余额。
- **兑换记录**：展示权益、核销码、时间、消耗积分。

### 关键文件
- Mock 接口：`features/platform/CarbonInclusiveClient.ets`（`Benefit`、`ApiResult`、8 项权益、`mockDelay`，`ENABLED=true`、`MODE='mock'`）。
- 数据：`data/repository/PlatformRepository.ets`（余额/同步时间/兑换事务/订单）。
- 页面：`pages/CarbonInclusivePage.ets`。

### 真机接入点（对接真实碳普惠服务）
1. `module.json5` 声明 `ohos.permission.INTERNET`。
2. 将 `CarbonInclusiveClient` 的 mock 方法替换为 `@kit.NetworkKit` 的 `http.createHttp()` 调用：
   - `GET /account/points` 查询余额；`POST /points/sync` 上报积分；
   - `GET /benefits` 权益目录；`POST /benefits/exchange` 兑换。
3. 上报携带本地记录 `uuid`/日期，服务端去重（幂等）；兑换以服务端结果为准。
4. 正式环境使用 HTTPS + 应用签名校验 / AccessToken，密钥不明文硬编码。

## 四、智能服务 · 个性化任务推送 / 生活建议 / 社交分享

### 已实现（可直接演示）
- 入口：「我的 → 📢 智能服务·提醒建议与分享」。
- **个性化今日重点**：统计近 7 天四类减排，找出最薄弱分类，推荐对应任务（绿色出行/节约用电/旧物回收/光盘行动），"立即去完成"直达该分类录入页；新用户无数据时给出绿色出行引导。
- **低碳生活建议**：最薄弱分类针对性建议 + 打卡/种树鼓励，纯本地规则。
- **通知推送（真实下发）**：点击"立即发送今日低碳提醒"调用 `@kit.NotificationKit` 的 `notificationManager.publish`，在通知栏展示。
- **成果社交分享**：生成"低碳成绩单"卡片（累计减排、积分、徽章、认种树木、连续打卡）：
  - "分享成果"通过 `@kit.AbilityKit` 的 `Want` + `ACTION_SEND_TO_DATA` 拉起系统分享面板（Stage 模型，API 26）；
  - "复制文案"通过 `@kit.BasicServicesKit` 的 `pasteboard` 写入剪贴板，作为无分享应用时的兜底。

### 关键文件
- 能力：`features/smart/SmartService.ets`（`buildFocus`、`buildTips`、`buildShareText`、`pushLocalNotification`、`shareText`、`copyText`）。
- 页面：`pages/SmartPage.ets`。

### 真机接入点（定时提醒 / 海报分享）
- 每日定时提醒：`scheduleDailyReminder` 注释中给出 `@kit.BackgroundTasksKit` 的 `reminderAgentManager.publishReminder`（`REMINDER_TYPE_DAILY`，如每天 20:00）示例，真机上取消注释即可。
- 通知需用户在系统设置中允许，首次使用应引导授权。
- 图片海报分享：可用 Canvas 离屏绘制"成绩单海报"导出图片，再通过系统分享发送图片（utd 用图片类型）。

## 五、权限配置清单

**当前本地演示版本无需在 `module.json5` 声明任何权限**：
- 相册选图使用 `PhotoViewPicker` 安全选择器，系统临时授权；
- 本地通知、系统分享、剪贴板、家庭/平台的本地模拟均无需额外权限。

真机接入时按需在 `entry/src/main/module.json5` 的 `requestPermissions` 添加（user_grant 需提供 `reason` 字符串资源与 `usedScene`）：

```json5
"requestPermissions": [
  { "name": "ohos.permission.DISTRIBUTED_DATASYNC" }, // 多设备同步
  { "name": "ohos.permission.CAMERA" },              // 拍照识别
  { "name": "ohos.permission.INTERNET" }             // 碳普惠联网
]
```

> 备份/导出使用 DocumentViewPicker，由系统选择器临时授权，无需声明存储权限。

## 七、（可选）从 JSON 备份恢复

当前已实现"导出"，如需"恢复"：
1. `picker.DocumentViewPicker().select()` 选择备份文件（`.json`）。
2. `fs.openSync(uri, OpenMode.READ_ONLY)` + `fs.readSync` 读取，`JSON.parse` 为 `BackupData`。
3. 在仓库中增加 `restoreFromBackup(data)`：用事务先清空业务表再按主键插入，`meta` 写回余额与昵称。
4. 恢复后自增 `AppStorage('refreshTick')` 刷新所有页面；恢复前二次确认避免覆盖。
